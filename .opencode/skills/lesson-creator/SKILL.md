# Lesson Creator

Створює уроки та модулі курсу **Python для олімпіад** за встановленими
конвенціями. Курс побудований на MkDocs + Material, інтерактивний Python
через Pyodide.

!!! info "Стек проєкту"

    - **MkDocs + Material** — генератор
    - **Pyodide** — Python у браузері
    - **GitHub Pages + Actions** — деплой
    - **Українська** мова

    Див. `mkdocs.yml` для повної конфігурації.

## Коли використовувати цей скіл

### Генерація модуля
- Користувач просить **"створи модуль N — Тема"** або **"implement module"**
- Потрібно **заповнити плейсхолдер модуля** (порожній `index.md` без уроків)
- Потрібно **розширити існуючий модуль** (додати урок або задачі)

### Генерація уроку
- Користувач просить **"створи/напиши/додай урок"**
- Потрібно **заповнити плейсхолдер уроку** (`docs/modules/m*-*/lessons/*.md`)
- Потрібно **розширити** існуючий урок новими прикладами чи задачами

### Генерація задач
- Користувач просить **"додай задачі до модуля"** або **"згенеруй задачі"**
- Кожен модуль **повинен мати сторінку задач** (`NN-tasks.md` в кінці) з
  5-10 олімпіадними задачами

## Коли НЕ використовувати

- Зміни в `mkdocs.yml`, CI, або структурі сайту → редагуй напряму
- Нові модулі (потребує узгодження структури) → попередньо обговори
- Стильові/деплой зміни → не стосується уроку

## Структура модуля (зафіксовано)

Кожен модуль має **стандартну форму**. При створенні нового модуля
створюй усі файли за цією схемою:

```
docs/modules/m<NN>-<slug>/
├── index.md                # Огляд модуля + список уроків + чек-ліст
└── lessons/
    ├── 01-<slug>.md        # Урок 1
    ├── 02-<slug>.md        # Урок 2
    ├── ...
    └── NN-tasks.md         # Сторінка задач модуля (ОБОВ'ЯЗКОВА)
```

### Що обов'язково генерується автоматично

!!! important "При створенні модуля завжди додавай задачі"

    Сторінка `NN-tasks.md` — це **окрема сторінка модуля**, яка містить
    5-10 олімпіадних задач на весь матеріал модуля. **Без неї модуль
    вважається неповним**.

    Задачі генеруються разом з модулем, а не додаються потім. Це гарантує
    що кожен модуль має практичну частину.

### Файли, які створюються при генерації модуля

| Файл | Призначення |
|---|---|
| `index.md` | Огляд модуля: тема, цільова аудиторія, список уроків, чек-ліст "після модуля" |
| `lessons/01-...md` ... `lessons/NN-...md` | Контентні уроки за шаблоном уроку |
| `lessons/NN-tasks.md` | **Сторінка задач модуля** — 5-10 задач з task-runner |

## Залочена структура уроку

Кожен урок **обов'язково** має таку будову. Відхилення можливі, але
повинні бути обґрунтовані.

```
1. Front matter             — title
2. Заголовок H1             — тема уроку
3. Вступ                    — 1-2 абзаци, що учень дізнається
4. Теорія                   — ключові концепції з прикладами
5. Де? Як? Коли?           — ОБОВ'ЯЗКОВИЙ блок про застосування
6. Типові помилки           — 2-3 поширені граблі
7. Задачі                   — 3-5 задач з підказками і розв'язками
8. Що далі?                 — посилання на наступний урок
```

### Front matter

```yaml
---
title: Змінні та типи даних
---
```

### Де? Як? Коли? — ключовий блок

!!! example "Шаблон блоку «Де? Як? Коли?»"

    ```markdown
    ---

    ## Де? Як? Коли?

    ### 🌍 Де це використовується в реальному світі?

    - **Сфера 1**: конкретний приклад з описом
    - **Сфера 2**: інший приклад
    - **Олімпіади**: де це зустрічається

    ### ⚙️ Як це працює в Python?

    - Як мова реалізує концепцію "під капотом"
    - Особливості синтаксису чи поведінки
    - На що звернути увагу (quirks)

    ### 🎯 Коли обирати / застосовувати?

    - **Умова 1** → обери варіант А
    - **Умова 2** → обери варіант Б
    - Чек-ліст прийняття рішення
    ```

**Цей блок обов'язковий** у кожному уроці. Без нього урок вважається
неповним. Мета — щоб учень розумів **практичну цінність** теми, а не лише
синтаксис.

## Генерація модуля (повний цикл)

Коли користувач просить **"створи модуль N — Тема"** або потрібно
заповнити порожній модуль, виконуй цей чек-ліст. **Все автоматично** —
від створення файлів до оновлення nav.

### Workflow створення модуля

```markdown
1. [ ] Визнач номер і slug модуля (m<NN>-<slug>)
2. [ ] Створи директорію docs/modules/m<NN>-<slug>/
3. [ ] Створи docs/modules/m<NN>-<slug>/lessons/
4. [ ] Створи docs/modules/m<NN>-<slug>/index.md (огляд)
5. [ ] Створи N уроків (зазвичай 5-7) у lessons/01-*.md ... NN-*.md
6. [ ] **Створи сторінку задач lessons/NN-tasks.md** ← ОБОВ'ЯЗКОВО
7. [ ] Додай модуль у mkdocs.yml → nav
8. [ ] Додай модуль у docs/index.md → таблиця огляду
9. [ ] Запусти mkdocs build --strict — переконайся, що все компілюється
```

### Сторінка задач модуля (`NN-tasks.md`)

!!! important "Обов'язкова при генерації модуля"

    Це окрема сторінка (не урок), яка містить 5-10 задач на **весь
    матеріал модуля**. На відміну від задач в уроках, тут — комплексні
    задачі, які поєднують кілька тем модуля.

**Структура сторінки задач:**

```markdown
---
title: Задачі модуля N — Тема модуля
---

<script type="application/json" data-tasks>
{
  "task-slug-1": [
    {"input": "...", "expected": "..."},
    {"input": "...", "expected": "..."}
  ],
  "task-slug-2": [...],
  ...
}
</script>

# Задачі модуля N — Тема

!!! info "Як працювати із задачами"

    Пояснення що тут комплексніші задачі...

## Розділ 1. Назва категорії

!!! task "Задача 1. Назва (Easy)"

    Умова з вхід/вихід/приклад.

    Спробуй сам:

    ```task-runner {data-task-id="task-slug-1"}
    # Стартовий код
    ```

    ??? hint "Підказка"
        ...

    ??? success "Розв'язок"
        ```python-runner
        ...
        ```

(повторити для 5-10 задач, згрупованих за категоріями)
```

**Вимоги до задач модуля:**

| Вимога | Опис |
|---|---|
| **Кількість** | 5-10 задач (типово 7) |
| **Категорії** | Групуй за темою (наприклад: "Рядки", "Списки", "Змішані") |
| **Складність** | Поступова: easy → medium → hard |
| **Кожна задача** | Умова + task-runner + hint + solution |
| **Тести** | 3-5 тестів на задачу, включно з edge cases |
| **Обмеження** | Для olympiad-рівня — додай обмеження (`n ≤ 10⁵`) і бажану складність |

**Генерація тестів:** для кожної задачі продумай:
- 1-2 "простих" тести (приклад з умови)
- 1-2 edge cases (`n=0`, `n=1`, максимальні значення)
- 1 "складний" тест (великі значення, граничні випадки)

Див. `references/tasks-template.md` — повний шаблон.

### Генерація `index.md` модуля

```markdown
---
title: Модуль N — Тема модуля
---

# Модуль N. Тема модуля

[вступ — 1-2 абзаци: навіщо модуль, що вивчимо]

## Уроки

1. [Урок 1 — Коротка назва](lessons/01-slug.md)
2. [Урок 2 — Коротка назва](lessons/02-slug.md)
...
N. [Задачі модуля](lessons/N-tasks.md) — комплексна практика

## Після модуля ви зможете

- [ ] Конкретна навичка 1
- [ ] Конкретна навичка 2
...
```

### Оновлення mkdocs.yml і index.md

Після створення файлів модуля **обов'язково**:

1. Додай у `mkdocs.yml → nav`:
   ```yaml
   - Модуль N — Тема: modules/m<NN>-<slug>/index.md
   ```

2. Додай у `docs/index.md → Модулі курсу`:
   ```markdown
   | N | [Тема](modules/m<NN>-<slug>/index.md) | Короткий опис |
   ```

3. Якщо це новий модуль — додай у `README.md` і `PLAN.md` відповідні таблиці.

## Інтерактивний Python (Pyodide)

Будь-який код, який учень може запустити, позначається fence'ом
` ```python-runner ` (а не просто ` ```python `). Стандартний
` ```python ` використовується для **неінтерактивних** прикладів: довгі
сніпети, фрагменти, псевдокод, вивід.

```markdown
\```python-runner
name = "Олімпія"
print(f"Привіт, {name}!")
\```
```

Pyodide завантажується **ліниво** (тільки при першому Run) і кешується.
Ctrl/⌘+Enter запускає код. Зверни увагу:

- Один runner — **один фрагмент** коду. Довгі програми розбивай на кілька
  runner'ів.
- Якщо програма потребує `input()`, учень бачить стандартну підказку
  (порожній stdin). Додай коментар-пояснення перед кодом.
- Для задач із введенням/виведенням використовуй runner з **підготовленими
  даними** через `input = lambda: ...` (перевизначення input) — інакше
  учень застрягне на очікуванні.

Приклад з перевизначенням `input`:

````markdown
\```python-runner
# Емулюємо введення: користувач введе "15"
input = lambda: "15"
age = int(input())
print(f"Через 5 років тобі буде {age + 5}")
\```
````

## Задачі з автоперевіркою (task-runner)

Кожна задача може мати **інтерактивне поле для розв'язку** з прихованими
тестами. Учень пише код і натискає **▶▶ Run Tests** — runner проганяє
його через усі тести й показує pass/fail по кожному.

### 1. Додай тести в script-тег

На початку уроку (після front matter) додай JSON із тестами. ID тесту
відповідає `id` у fence нижче:

```markdown
---
title: Змінні та типи даних
---

<script type="application/json" data-tasks>
{
  "swap": [
    {"input": "3 7\n",   "expected": "7 3"},
    {"input": "10 -5\n", "expected": "-5 10"}
  ],
  "rect": [
    {"input": "3\n4\n",  "expected": "12"},
    {"input": "5\n5\n",  "expected": "25"}
  ]
}
</script>
```

### 2. Використай fence `task-runner` з атрибутом `data-task-id`

````markdown
\`\`\`task-runner {data-task-id="swap"}
# Зчитай два числа через пробіл і виведи їх у зворотному порядку
\`\`\`
````

!!! warning "Чому `data-task-id`, а не `id`"

    MkDocs Material theme **перезаписує атрибут `id`** на `<pre>` для
    своїх потреб (копіювання коду, anchor links). Використання
    `id="swap"` призводить до того, що в браузері `id` стає `__code_5`,
    і тести не знаходяться. `data-*` атрибути MkDocs не чіпає — вони
    надійно зберігаються.

!!! warning "Синтаксис атрибутів"

    Pymdownx SuperFences вимагає **brace-синтаксису** для атрибутів:
    `{data-task-id="swap"}`, **не** `data-task-id="swap"` (без дужок).
    Дужки — обов'язкові, інакше fence не буде розпізнано.

Вміст fence — це **стартовий код**, який бачить учень. Може бути
порожнім або з коментарем-підказкою.

### 3. Структура задачі

```markdown
!!! task "Задача 1. Назва (Easy)"

    Умова задачі.

    **Вхід:** ...
    **Вихід:** ...
    **Приклад:** `input: "3 7" → output: "7 3"`

    ??? hint "Підказка"

        Ідея, не повний розв'язок.

    Спробуй сам:

    \`\`\`task-runner id="task-1-id"
    # Стартовий код (зайнятий коментар)
    \`\`\`

    ??? success "Розв'язок"

        \`\`\`python-runner
        # Повний робочий код
        \`\`\`
```

### Формат тестів

| Поле | Тип | Опис |
|------|-----|------|
| `input` | string | Дані, які подаються в stdin. `\n` — перенесення рядка |
| `expected` | string | Очікуваний stdout (без зайвих пробілів) |

Порівняння робиться з `strip()` — пробіли на початку/в кінці
ігноруються. Внутрішні пробіли — **значущі** (`"7 3" != "7  3"`).

### Конвенції для тестів

- **3-5 тестів** на задачу. Мінімум — happy path + 1 edge case.
- Починай із **простих** тестів, поступово ускладнюй.
- **Edge cases** для олімпіад: `n = 0`, `n = 1`, максимальні значення,
  від'ємні числа, порожні рядки.
- Тести з плаваючою комою — обережно: `0.1 + 0.2 != 0.3` через
  похибки заокруглення. Використовуй цілочисельні формули або
  заокруглення.
- **Не показуй очікувані значення** в тілі задачі — тільки приклад
  (input → output). Решту тестів учень бачить лише після запуску.

### Коли НЕ використовувати task-runner

- Задачі на **читання коду** (знайди помилку) — там немає що
  валідувати.
- Задачі-тести на **знання** (що робить цей код?) — без валідації.
- Задачі з **дуже розмитим виводом** (наприклад, "вивести всі прості
  числа") — порівняння stdout утруднене, краще дати просто
  `python-runner`.

## Задачі

!!! example "Шаблон задачі"

    ```markdown
    !!! task "Задача N. Назва"

        Короткий сюжет (1-2 речення). Умова:

        **Вхід:** перший рядок — `N` (1 ≤ N ≤ 1000)
        **Вихід:** одне число — результат
        **Приклад:** `input: 5 → output: 25`

    ??? hint "Підказка"

        Натяк на ідею без повного розв'язку.

    ??? success "Розв'язок"

        ```python-runner
        n = int(input())
        print(n * n)
        ```
    ```

Конвенції задач:

- **3–5 задач** на урок. Рівні: easy (більшість), medium, hard (1-2).
- Кожна задача має **умову** у форматі «Вхід / Вихід / Приклад».
- Задача має **підказку** (collapse).
- Задача має **розв'язок** (collapse, з інтерактивним runner).
- Розв'язок містить **повний код** з input/output.
- Якщо задача олімпіадного рівня — додай обмеження складності.

## Чек-ліст якості уроку

Перед тим, як вважати урок готовим, перевір:

- [ ] Front matter з `title`
- [ ] H1 заголовок
- [ ] Вступ (1-2 абзаци)
- [ ] Теорія з прикладами
- [ ] **Блок «Де? Як? Коли?»** — обов'язковий
- [ ] Типові помилки (мінімум 2)
- [ ] 3-5 задач з підказками й розв'язками
- [ ] Посилання «Що далі?» на наступний урок
- [ ] Усі приклади коду, які можна запустити — у fence `python-runner`
- [ ] Усі задачі мають **task-runner** з тестами (окрім виняткових випадків)
- [ ] Тести в JSON — **3-5 штук**, з edge cases
- [ ] Урок проходить `mkdocs build --strict` без помилок
- [ ] Посилання на урок додано в `index.md` модуля
