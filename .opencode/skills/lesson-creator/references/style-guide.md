# Стилістичні конвенції уроків

Цей документ — додаток до `SKILL.md` скіла `lesson-creator`. Тут зібрані
стильові рішення, які роблять уроки однорідними й зручними для читання.

## Мова

- **Українська** — основна мова усього контенту.
- Транслітерація — уникаємо. Виняток: загальновживані терміни (ООП, URL).
- Англійські терміни — курсивом або в лапках при першому згадуванні:
  "*event loop*", "функція `print`".
- Звертання — на «ти» (воно дружніше й ближче учню).

## Заголовки

- `H1` — лише назва уроку (один на сторінку).
- `H2` — великі розділи («Теорія», «Де? Як? Коли?», «Задачі»).
- `H3` — підрозділи всередині `H2`.
- `H4` — використовуй рідко; для внутрішньої структури задач.

## Код

### Мовний fence

| Fence | Коли використовувати |
|---|---|
| ```` ```python-runner ```` | Код, який учень запускає й експериментує |
| ```` ```task-runner {data-task-id="..."} ```` | Поле для розв'язку задачі з автоперевіркою |
| ```` ```python ```` | Довгі приклади, фрагменти, псевдокод, чисто ілюстративний код |

### Коментарі в коді

- Коментарі українською, лаконічно. Пояснюють **намір**, а не дію:

  ```python
  # ✅ добре
  # рахуємо суму парних чисел
  s = sum(x for x in arr if x % 2 == 0)

  # ❌ погано
  # проходимо по arr і якщо x парний, додаємо до s
  ```

- Для позначення вхідних/вихідних даних у задачах — коментар-шапка:

  ```python
  # Вхід:  5
  # Вихід: 120
  ```

### Імена змінних

- Уникай однолітерних імен, крім загальноприйнятих (`i`, `j`, `n`, `x`, `y`).
- Для олімпіадних задач — імена з умови (`n`, `k`, `s`).

## Блоки admonition

Використовуй Material admonition з іконками:

| Тип | Призначення |
|---|---|
| `!!! note` | Нейтральне зауваження, додаткова інформація |
| `!!! tip` | Порада, найкраща практика |
| `!!! warning` | Застереження, на що звернути увагу |
| `!!! danger` | Типова помилка, що ламає код |
| `!!! example` | Розібраний приклад |
| `!!! task` | Умова задачі (через кастомний CSS) |
| `!!! abstract` | Резюме, ключові висновки |

Кастомні типи (`task`, `hint` через details, `complexity`) налаштовані
в `docs/assets/css/extra.css`.

## Довжина

- **Теорія** — 200–500 слів. Менше = надто стисло, більше = нудно.
- **Приклади** — 3–5 інтерактивних runner'ів на урок.
- **Задачі** — 3–5 штук, рівні easy/medium/hard.
- **Загальна довжина уроку** — орієнтовно 15–25 хвилин читання.

## Що робити, коли урок виходить занадто довгим

1. Розбий на два уроки.
2. Перенеси частину теорії в "додаткове читання" (секція в кінці).
3. Спрости приклади — залиш тільки ключові.

## Помилки, яких слід уникати

- **Переклад англійського на українську калькою**: не "ітерабельний
  об'єкт", а "об'єкт, по якому можна ітерувати".
- **Академічний тон**: пиши як досвідчений друг, що пояснює школяру.
- **"Просто запам'ятайте"** — не працює. Пояснюй **чому** щось працює.
- **Код без контексту** — кожен приклад має супроводжуватись 1–2 реченнями
  пояснення.
- **"Це тривіально"** — для учня, який бачить тему вперше, нічого
  тривіального немає.
